## MAX30102通信验收

预期：

```text
# MAX30102: address 0x57 ACK
# MAX30102: PART_ID=0x15 (expected 0x15), REV_ID=0xXX
# MAX30102: communication check PASSED; sampling not enabled
```

0xXX为版本占位。检查最多尝试三次；失败时报告错误后继续SYS心跳。接线调整先断电，检查只在启动执行。

## PPG采集与PC记录

用户已提供MAX30102的0x57 ACK、PART_ID=0x15、REV_ID=0x03与通信PASSED记录。

采集配置为红光+红外、100 Hz、18位、411 us、ADC量程4096 nA、每通道LED标称7.2 mA、平均=1。使用10 ms轮询批量读取FIFO，INT暂未启用。FIFO不滚动覆盖，串口输出与读取分任务，以128帧队列连接；队列满则丢弃新帧并计数。

输出协议见ppg_protocol.md。先烧录查看PPG行，再关闭VS Code Monitor。在ESP-IDF终端从工程根目录运行：

```powershell
python tools/serial_logger/record.py --port COM6 --seconds 60
```

COM6替换为实际端口。该环境已有pyserial；独立Python环境需安装tools/serial_logger/requirements.txt。工具保存raw.txt、ppg.csv、system.csv、summary.json与最后10秒的ppg.svg，默认放在data/raw/时间目录；工具运行不会自动重启开发板。Ctrl+C可提前安全结束。SVG双通道独立缩放，无滤波，断点处不连线；自动缩放可能放大噪声，看到曲线不代表已有可靠脉搏波。

建议先空载记录10秒，再指腹轻盖发光/接收窗口，保持静止20秒，最后移开手指。不要用力压紧。观察RED/IR基线变化与周期性波形，预计每秒约100个配对样本。检查FIFO溢出、队列丢样、I²C错误与序号缺口；正常静止测试目标为这些计数保持0。可见红光弱/暗不能替代数据判断。

验证前不要据此计算或报告心率/血氧。手指成功后再研究腕部佩戴信号。

## 实时波形与采样质量

关闭VS Code Monitor后，在工程根目录的ESP-IDF终端运行：

```powershell
python tools/serial_logger/record.py --port COM6 --seconds 60 --live
```

同一个程序同时读取、显示和保存，避免多个程序抢占串口。窗口显示最近6秒RED/IR原始值，各自自动缩放；关闭窗口或Ctrl+C结束记录并保存。当前本机IDF Python已检查可用Tk 8.6和pyserial 3.5。其他环境若不支持Tk，去掉--live仍可采集并生成SVG。

记录还会生成quality.json：按重启会话分别统计有效接收速率、序号缺口、估算时间间隔、采集epoch变化、ADC饱和和错误计数增量。计数起止值区分历史错误与本次记录期间增加的错误；不能把硬件丢样下限当精确值。曲线自动缩放会放大噪声，不把曲线周期性或数据变化直接当成心率/血氧可靠性的证明。

第一轮测试：空载10秒、指腹静止30秒、轻微移动10秒、恢复静止10秒。重点查看静止时能否出现重复脉搏波、两路是否饱和，以及质量统计中的错误是否增加。空载与运动是对照条件，不需要在这些阶段得到稳定脉搏波。

截至当前，用户已反馈放手指后RED/IR数值变化，确认光学响应；完整原始记录、波形与采样质量尚待验证。该工具不输出心率或血氧。
