# EV9-AS6221温度采集

接线：VCC→3V3、GND→GND、SDA→IO4、SCL→IO5、ADD0→GND、ALERT/ADD1→GND。选择7位地址0x48，报警功能不使用。EV9模块已有稳压、上拉和电平转换，按丝印接线。采用独立I²C1，100 kHz，PPG仍使用I²C0。

配置寄存器0x01读-改-写，保留其他字段，设置CR=10（目标4转换/秒）、SM=0和SS=0，回读确认速率/连续模式。首次/恢复等待350 ms后读取温度，避免把启动寄存器的0当成已完成转换。温度寄存器0x00为MSB先发的16位二进制补码，每LSB=1/128°C；分辨率不是测量准确度。

```text
TEMP,seq,rx_us,temperature_c,valid,i2c_errors,config,status
```

序号每次输出递增；rx_us为ESP32读取结束时间，与PPG/IMU同钟但不是芯片转换时刻。CONFIG为16位回读十六进制值。通信失败时温度占位-999、valid=0；超出-40～125°C的原始换算值保留、valid=0；零和负温度可正常有效。地址/配置失败每5秒重试，其他模块继续运行。

上位机新增温度页，显示摄氏数值和最近120秒趋势；无效或3秒未更新显示--，错误/缺口处断线。保存temperature.csv与temperature_quality.json，区分记录数、有效数、接收率和错误增量。

烧录后运行 `python tools/serial_logger/record.py --port COM6 --seconds 60 --live`。先室温静置，再用指腹接触传感器观察变化与响应延迟；远离主控和稳压器热源。当前只表示模块/接触位置温度，贴肤结构、热源影响和参考温度对照尚未验证，不等于核心体温。

器件地址应答和配置回读用于通信验证，不是唯一器件ID认证。硬件实测待完成，资料依据EV9-AS6221模块原理图与AS6221 DS000751 v2-00。

## 软件检查

ESP-IDF v5.5.5编译通过，15项主机测试通过；AS6221测试使用同一C转换函数，覆盖数据手册正/负/零温度向量和范围，PC侧验证错误值不参与统计。混合PPG/IMU/METRIC/TEMP离线记录通过；隐藏Tk窗口检查通过温度页、趋势、通信失败与过期状态。实际温度读取和接触响应待用户烧录后验证。自动串口诊断工具已增加TEMP统计与AS6221启动日志，便于后续直接检查。

## 4 Hz响应优化（2026-10-14）

芯片连续转换改为4 Hz，主控读取周期250 ms，不增加平滑或预测算法。首次等待350 ms覆盖一个转换周期与转换时间，初始化超过读取周期时重置任务节拍，避免启动后补发一串重复读数。上位机从CONFIG实际位解码转换率，同时标明读取目标4 Hz；旧固件1 Hz数据仍可读取，不把它显示成已更新的4 Hz。

此前4份温度记录各60条，约1 Hz，读取均有效、I²C错误为0。升温和冷却仍可能由接触与板级热平衡主导；4 Hz减少更新等待，不代表物理响应或测量准确性提升。此版需重新烧录，检查TEMP间隔约250 ms及配置CR=10，再重复静置、接触和松开实验。
