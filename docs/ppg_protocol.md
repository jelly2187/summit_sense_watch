# PPG原始记录协议

```text
PPG,seq,time_us_est,red,ir,flags,fifo_lost_min,queue_lost,i2c_errors,epoch
```

这是字段说明，固件用PPG_FIELDS注释输出说明；数据行以PPG开头。SYS心跳格式保持不变，注释以#开头。

- seq：成功从FIFO读取的样本对序号；输出队列丢弃会造成序号缺口。硬件丢样不一定造成序号缺口。
- time_us_est：S3的FIFO指针快照时间，按100 Hz周期回推该批样本时间；不是芯片逐样本时间戳，存在轮询、传输和时钟误差。FIFO溢出时真实时间更不确定，不应跨越缺口分析间期。
- red、ir：18位原始ADC值(0..262143)，无滤波、没有转换为生理指标。
- flags位：1=FIFO溢出；2=此前输出队列丢样；4=某通道达到ADC上限；8=错误恢复后重新配置；16=估计时间调整以保持单调。缺口标志保留到下一成功入队帧，饱和逐帧检查。
- fifo_lost_min：本次启动累计观察到的硬件溢出计数下限；硬件单次计数在31饱和，不能当作精确丢样数。
- queue_lost：本次启动输出队列丢样数。
- i2c_errors：读取或恢复错误次数。
- epoch：恢复配置后递增，跨epoch不连续；软件重启全部计数归零。

读取错误可能产生部分传输，因此下一轮重置传感器和FIFO并标记新epoch。被重置时未读FIFO样本数未知，不计入fifo_lost_min；必须同时检查epoch和错误标志。初始化失败时只保留心跳，修复接线后重新启动。

PC的session根据序号回退区分启动会话，pc_receive_ns记录PC单调接收时间，不替代设备采样时间。summary的序号缺口是串口可见缺口，硬件溢出另记；多会话计数取最大值，完整逐会话信息在CSV与raw日志中。不要把两类丢样数直接相加，避免重复计数。
