# 亚博十轴IMU集成与验证

## 接线与初次启动

断电接线：IMU 5V→S3 5V，GND→GND，TX→IO18，**RX→IO17**。之前仅接三根线可读取默认运动数据；第四根线用于主控开启气压输出。IMU自身USB暂不接电脑，避免同时配置。GPIO对应板上丝印。

UART1使用9600、8N1。若模块曾修改过波特率，先通过厂家上位机确认实际配置，再修改board_config中的BOARD_IMU_BAUD。启动约1.2秒后固件发送解锁、输出内容0x005E和10 Hz请求，并读取寄存器回验。不改变波特率、不执行校准/高度清零、不保存到模块Flash。只有收到回验/气压帧才表明配置实际生效；发送成功本身不表示模块已接受。

默认请求ACC/GYRO/ANGLE/MAG/PRESS，每类目标10 Hz。尚未收到气压帧时界面显示--并提示RX接线，不虚构高度。

## 输出与单位

```text
IMU,kind,seq,rx_us,v1,v2,v3,v4,valid_mask
IMU_STAT,rx_us,frames,checksum_errors,discarded_bytes,uart_errors,pressure_frames,angle_frames,online,configured
```

valid_mask每一位代表对应v1..v4有效。缺失字段仍占位为0，但不能作为有效测量。kind对应：

| kind | v1 | v2 | v3 | v4 |
|---|---|---|---|---|
| ACC | ax(g) | ay(g) | az(g) | 模块温度(℃) |
| GYRO | gx(°/s) | gy(°/s) | gz(°/s) | 无效占位 |
| ANGLE | Roll(°) | Pitch(°) | Yaw(°) | 固件版本号 |
| MAG_RAW | hx(原始计数) | hy | hz | 模块温度(℃) |
| PRESS | 气压(Pa) | 模块高度(m) | 无效占位 | 无效占位 |
| QUAT | q0 | q1 | q2 | q3 |
| REG | 输出内容RSW | 速率代码 | 波特率代码 | 相邻寄存器 |

QUAT可解析但本轮未请求输出。ACC按协议固定16g/32768换算，GYRO按2000°/s/32768换算，欧拉角按180°/32768。IMU温度不替代AS6221贴肤温度。压力范围30000～110000 Pa之外保留数值、标记无效。

串口帧固定11字节，以0x55开头，前10字节和的低8位为校验；支持拆包、连包与校验失败后重新寻找帧头。seq是MCU分配的输出帧编号，不是模块硬件序号；不能仅靠seq连续证明没有传感器丢帧。rx_us是S3收到字节块的时间，与PPG使用同一时钟，但不同IMU字段独立发送，不保证它们同一时刻测量。

## 上位机

重新烧录后，关闭Monitor并运行：

```powershell
python tools/serial_logger/record.py --port COM6 --seconds 60 --live
```

PPG页保留原波形和生理估算；IMU页新增加速度、角速度、角度、气压和高度曲线及三维板状模型。模型使用Rz(Yaw)Ry(Pitch)Rx(Roll)，对应X横滚、Y俯仰、Z偏航。数据超过2秒未更新显示失效，不继续显示旧角度。气压高度标为未校准模块输出，相对高度以第一次有效高度为起点；零点按钮只改变显示，不改模块，不改CSV。

这不是经过安装校准的绝对空间姿态/真北指示。Yaw依赖模块磁场/姿态算法，受附近电子设备、磁铁及安装方式影响。气压高度也受气压漂移与模块基准影响，不能直接认定为准确海拔。三维展示暂使用模块已解算欧拉角，±180°换绕时曲线断开，不绘制虚假跨越线。

保存新增imu.csv、imu_status.csv、imu_quality.json，原PPG与METRIC格式保持。质量文件按字段和启动会话统计接收率；高采样率集成以后可能需要提高PC串口波特率，目前10 Hz与115200串口先实测。

## 验收

1. 模块静置：ACC合模约1 g，GYRO接近0，姿态变化较小。
2. 分别绕X/Y/Z缓慢旋转：角度、三维模型方向及角速度变化对应。
3. 检查PRESS帧出现、气压量级合理；提高/降低模块观察模块高度趋势，避免把天气漂移当爬升。
4. 全模块记录60秒，复查PPG丢样、IMU校验错误/串口溢出、各类字段频率与内存状态。
5. 暂不实现步数/步频，不修改既有生理质量算法；先获得同步运动记录。

协议依据：[亚博官方十轴通信协议](https://www.yahboom.net/public/upload/upload-html/1656404467/10-axis%20IMU%20module%20communication%20protocol.html)及本地对应PDF和STM32官方SDK。驱动为本项目独立实现，硬件接线和配置生效待实机验证。

## 本次软件验证

ESP-IDF v5.5.5固件编译通过。11项测试通过（6项IMU协议/客户端测试，5项既有生理算法测试）；IMU覆盖有符号单位、拆包/连包、校验失败恢复、压力与负高度、未使用帧、客户端有效位与三维旋转轴。混合PPG/METRIC/IMU离线记录检查通过。隐藏Tk窗口测试覆盖页面创建、3D绘图、气压显示和姿态过期失效。上述测试不替代实物接线、模块配置回验及PPG+IMU连续采集验证。

## 气压缺失排查更新

20261013_221340_582641记录中ACC/GYRO/ANGLE/MAG_RAW各603帧，约10 Hz，校验及UART错误为0；没有PRESS或REG帧，配置确认状态为0。因此当前缺失发生在模块输出/命令通路，不是上位机隐藏了有效气压。用户已确认补接RX→IO17并重启。

诊断版按厂家SDK逐寄存器单独解锁，用20 ms间隔，最多三次请求开启气压与回读，间隔约3秒。不保存配置、不改变串口波特率。启动日志打印configuration attempt、TX status和实际register response；ESP_OK只表示本地发送成功。需重新烧录后打开Monitor并按RESET，收集启动后约10秒的# IMU日志。若收到RSW=0x005E、RATE=0x0006但仍无PRESS，再核对模块型号和厂家上位机输出；若没有任何REG回读，优先定位双向UART命令通路。

## 气压输出已验证：USB预配置方案

2026-10-13直接连接IMU自身CP210x串口COM7，以9600 baud读取RSW=0x001E。发送解锁与RSW=0x005E后收到0x56气压/高度帧，寄存器回读为0x005E，RATE=6、BAUD=2。确认有效压力数据后发送SAVE=0保存输出设置。

用户拔掉IMU自身USB、断电后恢复三线：5V→5V、GND→GND、TX→IO18，RX暂留空。随后通过ESP32 COM6自动捕获10秒，收到100帧有效PRESS；示例气压101255 Pa、模块气压高度5.96 m，校验和UART错误均为0。这验证了设置在重新供电后保留、模块和固件压力解析链路可用。

当前采用“USB预配置、ESP32只接收”的接入方式，不需要更改现有上位机。configured=0表示ESP32命令通路没有确认寄存器回读，不表示已收到的PRESS无效。ESP32→IMU发送通路仍待单独排查，不能据USB成功认定它已修复。

诊断记录：data/raw/20261013_223545_970123_imu_usb（临时开启）、20261013_223649_208520_imu_usb（保存）、20261013_223845_358856_diagnostic（断电回接验证）。工具imu_usb.py支持直接USB读取/开启，仅在有效气压和目标RSW回读均通过时允许--save；诊断数据独立备份。

目前验证是静止数据接收。抬高/降低模块的动态高度响应、气压漂移及海拔基准仍未验证。5.96 m是模块的未校准气压高度，不是已验证的真实海拔；UI相对零点只改变显示。
